THE SINGLE CHANGE
- Baseline file: camera_baseline.html, Ink threshold slider = 140.
- Final file: camera_final.html, Ink threshold slider = 97. Nothing else was changed.
- How the slider works: segment.js computes a cutoff from each image and adds (slider - 140) x 0.4, limited to 40-230. A pixel counts as ink if it is darker than the cutoff. So 97 lowers the cutoff by about 17: fewer grey pixels count as ink.
- Reason: I wanted to see whether a stricter ink cutoff removes grey shadow/paper pixels from the 28x28 input and changes the predictions.

REFLECTION
I changed the ink threshold from 140 to 97 because I wanted to see whether a stricter cutoff gives a cleaner 28x28 input. Before: 100%; after: 100%. Accuracy did not change and the mean score went down slightly (0.9965 to 0.9925), so in these conditions the change did not help.
One limitation is that ten clear cards in one lighting setup are too easy: both versions scored 100%, so the test cannot show a difference. The faint 0 also showed that thin, weak strokes can be lost completely.
Next I would test the same two settings on a harder set (thin pens, shadows, slightly tilted cards, other people's handwriting) with more cards per digit.
